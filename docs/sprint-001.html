Sprint 1: Core Loop MVP

Epic: EPIC-001 Goal: Playable first floor Status: Planned

Player can start a run, move through a generated floor, fight enemies, and reach the exit to progress to the next floor.

Tasks

SC-001 — Project scaffold

  • Initialize Next.js with TypeScript
  • Install Phaser.js (phaser npm package)
  • Create directory structure per AGENTS.html
  • Configure npm run dev / build / lint
Acceptance: npm run dev starts, browser shows blank page with Phaser canvas mounted.

SC-002 — Title screen + game page

  • Next.js page at /: title screen with PRESS ENTER TO START
  • Next.js page at /game: mounts Phaser game instance
  • BootScene loads base sprite assets, transitions to DungeonScene
Acceptance: Hit Enter on title → navigates to /game → canvas renders.

SC-003 — Floor generation API

  • POST /api/generate/floor accepts a seed or floorNumber
  • Returns JSON: { map, enemies, items, boss }
  • Prompt template in game/generation/prompt.ts
  • Parser validates LLM output before returning
  • Seed → deterministic generation for debugging
Acceptance: Calling the API returns valid game data. Invalid LLM output is caught and retried.

SC-004 — Tile map rendering + collision

  • Render 2D tile array as Phaser tilemap
  • Tile types: floor, wall, door, exit
  • Collision system: solid tiles block player/enemies
  • Rooms connected by door tiles
Acceptance: Generated map renders. Player cannot walk through walls. Doors lead to adjacent rooms.

SC-005 — Player entity

  • WASD movement (real-time, 8-direction)
  • Mouse aim + click to shoot projectiles
  • Health bar (top-left HUD)
  • Simple circle sprite (placeholder)
Acceptance: Player moves smoothly, shoots projectiles that travel and collide with walls/enemies.

SC-006 — Enemy entities

  • 2 types per run (defined by API response)
  • Chase AI: move toward player when in detection range
  • Enemies take damage from projectiles, die after X hits
  • Enemies damage player on contact (knockback + iframes)
Acceptance: Enemies chase and damage player. Player can kill them. New enemies spawn per room.

SC-007 — Weapon + item system

  • 1 weapon per run from API response
  • Weapon defines: damage, fire rate, projectile speed, name
  • Pickup UI shown on room entry
  • Health pickups from defeated enemies (optional MVP scope)
Acceptance: Weapon stats affect gameplay visibly. Picking up a new weapon changes behavior.

SC-008 — Exit door + floor progression

  • One exit tile per floor (marked on map)
  • Player touching exit → calls API for next floor
  • Brief "Floor N" transition screen
  • Health carries over between floors
Acceptance: Reaching exit generates a new floor. Player continues with remaining HP.

SC-009 — Death + restart

  • HP hits 0 → death screen with run summary
  • Press Enter → return to title screen
  • Run summary generated from tracked stats
Acceptance: Player dies, sees summary, can restart a fresh run.

Definition of Done

  1. Every task AC met and manually play-tested
  2. npm run build passes with no errors
  3. npm run lint passes
  4. No console errors in browser during gameplay
  5. Sprint summary written to docs/sprint-001-review.html

Architecture Notes

  • Phaser game instance managed via React ref in /game page
  • All game state lives in Phaser scenes (not React state)
  • API calls from Phaser scenes via fetch
  • Sprite recipes: hardcoded JSON templates for MVP, expanded later
  • LLM prompt returns structured JSON — parse with JSON.parse + validation
